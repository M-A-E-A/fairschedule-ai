## 2. What was built this round, mapped to requirements

### Backend (was red at baseline: 204 collection error, 148 Ruff errors, 13 broken tests)

- **204 responses fixed** â€” FastAPI route handlers on `DELETE` endpoints in
  `admin.py`, `bookings.py`, `rooms.py` now return an explicit
  `Response(status_code=204)` with a `-> Response` annotation. Reason: with
  `from __future__ import annotations`, `-> None` is resolved by FastAPI to
  `NoneType`, which is truthy, so FastAPI asserts a response body is present and
  the 204s failed at collection time.
- **Ruff/B008 resolved by configuration, not by restructuring code** â€”
  `backend/ruff.toml` contains:

  ```toml
  [lint.flake8-bugbear]
  extend-immutable-calls = [
      "fastapi.Depends",
      "fastapi.Security",
      "app.api.deps.require_roles",
  ]
  ```

  **Reasoning (as required):** B008 flags *function calls in argument defaults*.
  FastAPI's dependency-injection design is explicitly built around argument
  defaults â€” `def endpoint(user: User = Security(require_roles(...)))` IS the
  documented idiom (FastAPI docs, "Dependencies with `yield`", "OAuth2",
  "Classes as dependencies"). Rewriting every endpoint to avoid a call in a
  default would mean either re-instantiating dependencies inside each handler
  body (losing FastAPI's dependency graph, caching, OpenAPI documentation, and
  `Depends`-in-`Security` composition) or adding an `Annotated` alias per
  endpoint purely to silence a linter â€” a mechanical refactor with zero
  behavioural gain that would make the code *less* idiomatic, not more. The
  values passed (`Depends`, `Security`) are FastAPI's own dependency markers;
  they are evaluated once at route definition, are immutable by design, and can
  never be mutated later in a way B008 is meant to catch. Declaring them in
  `extend-immutable-calls` tells Ruff exactly that, which is the configuration
  mechanism the Ruff authors provide for this precise situation. No code was
  restructured; the idiomatic `Depends()`/`Security()` pattern is intact.
- **Missing `import sqlmodel`** added to Alembic migration
  `72bbb9943009_initial_schema.py` â€” a genuine runtime bug that broke every
  `alembic upgrade head`.
- **13 broken tests fixed by fixing the test code, never by weakening assertions**:
  `module_login(client, username)` fixture signature corrected to match its 10
  call sites; `start=630` â†’ `start=540` in three scheduler tests (comments say
  "same original slot"; the half-open overlap semantics were kept); harbor-admin
  password passed explicitly as `demo-admin-harbor`; `timetable['sessions']`
  envelope key; `'Harbor Institute'` â†’ `'Harbor College'` (the seed is

  `'demo-x'` â†’ `'demo-sample'` (the 8-char password policy was kept);
  `full_name` made optional in `CreateUserRequest` (default `''`).
